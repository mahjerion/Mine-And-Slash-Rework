# Library-of-Exile-Rework — class-level map

Deep-dive detail for `## Submodules` in CLAUDE.md — read before working inside `Library-of-Exile-Rework` itself or tracing a core abstraction back to its source.

Package root `com.robertx22.library_of_exile` (plus `com.robertx22.orbs_of_crafting`, same jar).

- **Registry / content database** (`registry/`) — what `mmorpg`'s `ExileDB` and every addon's `*Database` are built on. A content type implements `ExileRegistry<C>` (`GUID()`, weight, `ExileRegistryType`); `JsonExileRegistry<T>` instead makes entries datapack-serializable/reloadable — `compareLoadedJsonAndFinalClass` round-trips each through Gson on load and logs a "Datapack Check Failed" diff on mismatch. `ExileRegistryType` defines a type's `id`, load `order`, `SyncTime`. `Database`/`ExileRegistryContainer` hold registered entries per type; `LibDatabase` is the Library's own content accessor (leagues, affixes, relics, mob lists, map data blocks, map finish rarities).
- **Capabilities** (`components/`) — `ICap extends ICapabilitySerializable<CompoundTag>`; `syncToClient` pushes via `Packets` → `SyncPlayerCapToClient`. Every per-entity/-chunk/-map/-world data class in the mod and addons implements this.
- **Custom event bus** (`events/base/ExileEvents`) — Forge-independent (`ExileEventCaller` + `EventConsumer`), used to decouple cross-mod hooks: damage phases (`DAMAGE_BEFORE_CALC`/`AFTER_CALC`/`BEFORE_APPLIED`), `MOB_DEATH`, `MOB_KILLED_BY_PLAYER`, `ON_CHEST_LOOTED`, mining events, `AFTER_DATABASE_LOADED`, `ON_PLAYER_LOGIN`, `CHECK_IF_DEV_TOOLS_SHOULD_RUN` (how `LibraryOfExile.runDevTools()` asks the host mod whether dev tools are on). Addons register listeners here instead of depending on each other directly.
- **Map/league dimension framework** (`dimension/` + `config/map_dimension/`) — shared machinery for "enter an instanced map dimension" leagues. A mod describes its dimension with `MapDimensionInfo` (dimension key, primary `MapStructure`, extra content structures, `MobValidator`, defaults), registers via `MapRegisterBuilder`, supplies a chunk-gen consumer (`MapChunkGenEvent`). `MapDimensions.isMap(level)`; there's a dimension/folder wipe feature. This is why the three addons look nearly identical structurally.
- **Crafting currency** (`orbs_of_crafting`) — `Orbs`, `Modifications`, `Requirements`, `OrbEdits` (registered as key holders in `LibModConstructor`); orbs apply modifications/requirements to items. Main mod wires in via `OrbAddonEvents.register()`.
- **Mod bootstrap helpers** (`main/`) — `LibModConstructor`/`OrderedModConstructor` (deterministic multi-mod registration order), `ApiForgeEvents.registerForgeEvent(...)` (standard way these mods add Forge listeners), `ExileLog`, `Packets`, data-gen bases (`LibDataGen`, `LibLootTables`).
